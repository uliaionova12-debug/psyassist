# Naming Convention

Правила именования файлов внутри `Product Media Kit/`.

## Финальные карточки (`02_Final Cards/`)

Формат: `<номер>_<английский технический слаг>.png`

Примеры:
```
001_supervision_menu.png
002_main_menu.png
003_profile_menu.png
```

- **Номер** (`001`, `002`, …) — задаёт порядок карточек в библиотеке. Порядок фиксируется в `Screen Library Index.md`; при изменении порядка меняются номера файлов, а не только запись в индексе.
- **Технический слаг** — короткое английское название экрана/раздела (`main_menu`, `client_dynamics`, `chat_analysis`). Нужен для GitHub, поиска по репозиторию и автоматизации (скрипты рендера в `01_Working Layouts/`). Не переводится на русский и не меняется без необходимости — на слаг могут ссылаться скрипты генерации.
- Русские названия (заголовок карточки, название экрана) используются только в документации (`Screen Library Index.md`, README) — не в имени файла.

## Черновики, варианты, коллажи

Любой файл, который не является финальной утверждённой карточкой, должен быть явно помечен, чтобы не смешиваться с `02_Final Cards/`:

- Черновые варианты шаблона — в `01_Working Layouts/Card_Template_Variants/`, с суффиксом варианта (`Card_Template_A_Conservative.png`, `Card_Template_B_Balanced.png`).
- Тестовые/QA-рендеры — не хранятся в `Product Media Kit/`, только во временной scratch-директории сессии.
- Коллажи, инфографика и прочие материалы, не построенные по `Card_Template.html`, не получают номер в стиле `001_…` — это зарезервировано только за карточками библиотеки. Такие файлы перечисляются отдельно в `Screen Library Index.md` (раздел «Не относится к библиотеке экранов»).
- Исключённые из библиотеки карточки не удаляются и не переименовываются — переносятся в `02_Final Cards/_excluded/` с исходным именем и номером, который они имели на момент исключения.

## Номер не переиспользуется

Номер карточки после утверждения закреплён за ней навсегда, даже если карточка позже исключена из библиотеки. Если карточка `019` исключена, номер `019` остаётся зарезервированным — присваивать его новой карточке нельзя без отдельного решения. Это нужно для стабильности ссылок на карточки (в `Screen Library Index.md`, в других документах, в возможной автоматизации) — номер должен однозначно указывать на один и тот же файл в любой момент времени.

## Исходные скриншоты (`00_Original Screenshots/`)

Исходники сохраняют имя, присвоенное при экспорте (`IMG_8594.PNG` и т. п.) — переименование не требуется, так как связь «скриншот → карточка» фиксируется в `Screen Library Index.md`, а не в имени файла. Исключение — специально подготовленные демонстрационные скриншоты (например, `Скрин библиотека кейсов.png`): по возможности им стоит присваивать понятное русское или английское название, отражающее назначение, поскольку они не пронумерованы камерой/устройством.
